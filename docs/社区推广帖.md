## 正文

### 背景

用 Nuclei 扫一圈，出来 50 条告警，其中 30 条是技术识别（"检测到 Nginx"），10 条是误报（教程页代码示例触发了 XSS 规则），真正需要看的漏洞不到 10 条。

我花四周时间做了个工具来解决这个问题。

### 做了什么

**NucleiAI** — 在 Nuclei 扫描引擎之上加了一层 AI 分析：

1. **AI 误报过滤**：Ollama 本地跑 qwen3:8b，批量分析扫描结果。不是简单的"调 API"，而是经过 5 轮 Prompt 迭代，加了场景化指引（教程页识别、转义检测、调试模式判断等）。
   - 现在也支持任意 OpenAI 兼容 API（DeepSeek / 火山方舟），本地模型和云模型自动切换。
   - 判定结果三分类：真实漏洞 / 误报 / **待人工复核**——LLM 分析失败时不会默认当成漏洞，必须人工确认。

2. **混合防线**：8B 量化模型不够稳定（同一数据 75%-100% 波动），所以加了 5 条硬规则兜底。比如"响应中 `<script>` 已被 HTML 实体编码 → 自动标误报"。AI 处理模糊判断，规则保证确定性场景不出错。

3. **自建靶场验证**：14 个真实漏洞 + 6 个误报干扰项，写了 20 个自定义 Nuclei 模板。最终准确率：漏洞确认 100%，误报识别 100%。

4. **真实网站能力**：BFS 爬虫（尊重 robots）+ 会话管理（Cookie / Bearer / 自定义头，可保存登录态）+ crt.sh 子域名枚举 + httpx 存活探测 + 全自动管线扫描，可加载官方社区模板（8000+）。

5. **工程与安全**：Web 面板可选访问令牌鉴权；pytest 22 例单元测试 + GitHub Actions CI；配置支持 config.local.yaml 覆盖和环境变量，不再硬编码本机路径；提供 Dockerfile 和一键启动脚本。

### 技术栈

```
扫描引擎: Nuclei v3.8 (Go)
AI 推理: Ollama + qwen3:8b (本地) 或 OpenAI 兼容 API (DeepSeek 等)
后端: Python FastAPI
前端: Jinja2 + 原生 CSS
靶场: Python http.server (零依赖)
质量: pytest + GitHub Actions
```

### 一些技术细节

- **批量分析优化**：逐条调 LLM 要 5 分钟，改成拼 Prompt 一次调用降到 1 分钟。意外发现批量分析还提升了准确率——LLM 看到全部上下文后相对判断更准。
- **响应预览 Bug**：排查了两天才发现 AI 一直看不到页面正文——`response.split("\r\n\r\n")[0]` 取的是 HTTP 头不是 body。改完准确率立竿见影。
- **指纹识别**：httpx 先跑一遍技术栈探测，检测到 Apache+PHP 就自动从 Nuclei 官方库匹配对应模板，不用全量扫描。
