# NucleiAI 面试话术准备

## 1. 项目概述（电梯演讲，30秒）

"我做了一个 AI 增强的漏洞管理平台 NucleiAI。它在 Nuclei 扫描引擎之上集成本地大模型，自动过滤误报并生成中文漏洞报告。核心创新是**混合防线设计**——AI 做语义理解，硬规则做确定性修正，准确率从 75% 波动提升到稳态 90%+。项目用 Python FastAPI + Ollama 本地部署，2000+ 行代码，20 个自编检测模板。"

---

## 2. STAR 法则详细回答

### Q1: 为什么要做这个项目？（Situation + Task）

**S:** 安全扫描器的最大痛点是误报率高。Nuclei 作为流行的开源扫描器，官方只做规则匹配不做智能分析。我调研发现，很多安全团队每天要花 30% 时间人工审核扫描结果。

**T:** 我的目标是在 Nuclei 之上构建一个 AI 分析层，自动区分真实漏洞和误报，并生成可交付的中文报告。这比"魔改 Nuclei 源码"更务实——Nuclei 已经是成熟的扫描引擎，我应该站在它的肩膀上做差异化。

### Q2: AI 误报过滤怎么做的？（Action — 技术核心）

**A:** 分三步走：

1. **批量分析优化**：最初逐条调 Ollama，9 条结果要 5 分钟。我把所有结果拼成一个 Prompt，单次 API 调用分析全部，降到 1 分钟。关键发现是批量分析还提升了准确率——LLM 看到全部上下文后，能更好地做相对判断。

2. **Prompt 工程 5 轮迭代**：从抽象规则到场景化指引。比如"标题含'教程'的页面通常是教学文章"比"区分教育内容和漏洞"有效得多。URL 路径是重要上下文——`/blog/xss-tutorial` 和 `/search?q=` 的语义差别对 LLM 判定帮助巨大。

3. **混合防线设计**：8B 量化模型存在固有波动（同一数据 75%-100%），所以加了 5 条硬规则自动修正——比如"响应中 script 标签已被 HTML 实体编码 → 自动标误报"，"重定向目标为内部路径 → 非开放重定向"。这就像自动驾驶的感知模型 + 规则引擎：AI 处理模糊判断，规则保证安全底线。

### Q3: 遇到的最大技术挑战？（Action — 问题解决）

**A:** 两个关键问题：

1. **响应预览 Bug**：AI 判定一直质量差，排查发现 `_summarize_result()` 用 `response.split("\r\n\r\n")[0]` 提取响应——这是 HTTP 头部，AI 根本看不到页面正文。改为同时提取头部和正文后，准确率立竿见影提升。

2. **干扰项不触发模板**：做误报测试时发现，干扰页面没有模板匹配关键词，模板根本不会触发，AI 也无从判定。解决方案是在干扰页 HTML 中保留字面量关键词（如在 `<pre><code>` 中放未转义的 `<script>` 标签模拟教程页），让模板触发后由 AI 来区分。

### Q4: 效果怎么样？（Result — 量化）

**A:** 在自建靶场（14 漏洞 + 6 误报干扰 = 20 端点，26 条检测结果）测试：
- 漏洞确认率 100%，误报识别率 100%（最终一轮）
- 混合防线保证稳态 90%+ 准确率，即使 AI 波动
- 扫描全链路 ~3-5 分钟（瓶颈在 Ollama，8B 模型推理 ~25s/批）
- 20 个自编模板覆盖 OWASP Top 10 主流漏洞类型

## 3. 常见追问

### Q: 为什么用本地模型不用 GPT-4？

"两个原因：一是成本——本地 Ollama 零 API 费用，适合持续扫描场景；二是数据安全——扫描结果可能包含敏感信息，不上传外部 API。同时架构上保留了切换到云端 API 的能力。"

### Q: 混合防线和纯 AI 方案的区别？

"纯 AI 方案的问题是 8B 量化模型不够稳定，同一输入多次测试准确率在 75%-100% 波动。硬规则处理的是**确定性场景**——比如 HTML 实体编码就是转义，Location 头以 `/` 开头就是内部跳转。这些不需要 AI 判断，代码层直接修正更快更准。"

### Q: 你怎么验证 AI 判定的正确性？

"搭建了含干扰项的漏洞靶场——6 个页面故意包含模板关键词但不构成漏洞（如教程页、已关闭的调试页）。对照实验：先确认模板正确触发，再验证 AI 正确分类。同时做多轮测试记录波动性。"
